# Agent rules

- Use smart engineering and minimal dependencies.
- Keep each change narrow and testable.
- Inspect existing code before adding abstractions.
- Follow `VOICE.md` only for Commitment’s own speech and public narration.
- Use clear, normal prose for engineering explanations and operator instructions.
- Preserve exact identifiers, filenames, commands, errors, and structured data.
- Distinguish current behavior from planned behavior. Do not claim that unbuilt features work.
- Run relevant tests and inspect the diff before declaring success.
- Never commit or push unless explicitly asked.
