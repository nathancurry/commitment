# Queue

This directory holds candidate future work generated by Commitment. It is separate from explicit human input, durable memory, and the runlog audit trail. A session need not create or change a queue item.

Use a normalized lowercase hyphenated title as the filename and this format:

```markdown
---
title: Short candidate title
status: candidate
priority: low | medium | high
origin: session, memory, issue, URL, or other reference
created: 2026-09-13
updated: 2026-09-13
memory: memory/example.md
sources: issue, URL, commit, file, or other references
---

## Value hypothesis

What usefulness, reliability, learning, autonomy, or demonstrated maintainability need this may improve.

## Next step

One concrete bounded action.

## Disposition

Required when status is `done` or `rejected`; explain the result or rejection briefly.
```

Allowed states are `candidate`, `researching`, `ready`, `blocked`, `deferred`, `done`, and `rejected`. Keep rejected items with their reason. Before creating an item, scan filenames, normalized titles, and exact origin references; update a match instead of duplicating it. This is a direct text scan, not semantic deduplication.
