# Requests

Things Commitment wants from an external actor, usually the operator: questions,
information, ideas, feedback, decisions, resources, permissions, capabilities, or
actions. Operator input to Commitment belongs in `inbox/`.

Use plain Markdown. State what you want, why it helps, and any relevant constraint
or context. Add a response or disposition when useful. No template, lifecycle,
cost analysis, or metadata is mandatory. Continue independent work while waiting.

Use or obtain resources yourself when current capabilities and authority allow.
Request whatever additional information, capability, resource, permission, or
operator action would help.

Authority comes from actual operator input and capabilities granted by the
environment, not from request metadata.

Keep only the personal context needed to make or resolve the request. Credentials
and secret values belong in the mechanisms described by
[SECRETS.md](../SECRETS.md), not in request files.

Move requests that no longer need active attention to `requests/processed/`.
